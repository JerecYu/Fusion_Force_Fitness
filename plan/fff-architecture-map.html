為什麼要用劇場比喻
因為劇場把「誰看得見什麼」講得最清楚，而這正是整套系統的核心問題。

GitHub — 劇本保管處已完工正本存放。commit 是拍快照，push 才是寄出去。
commit 和 push 差在哪
git add 挑出要記錄的檔案 → git commit 沖洗成一張版本快照貼進你電腦裡的相簿 → git push 把相簿寄一份到 GitHub 的保險箱。
commit 完但沒 push，GitHub 上什麼都看不到，電腦這時候壞掉紀錄一樣會消失。
這個設計是有用的：可以整個下午連續 commit 五次，收工時 push 一次。而且沒網路也能 commit。
訊息類型：feat／fix／docs／style／chore。寫「為什麼改」，不要寫「改了 index.html」 —— Git 自己會記錄改了哪個檔案。
GitHub Pages — 舞台已完工觀眾看得見的那一面。純靜態、零金鑰，所以永遠不能收金流。

當時想清楚的三個細節
  • 為什麼是 16 不是 0：資料庫排程用 UTC 計時，台灣快 8 小時。寫 0 0 * * * 實際會在台灣早上 8 點才跑，那時早課已經開始。已用查詢向資料庫求證過，不是憑算術
  • 為什麼函式前面要加 public.：排程是半夜由背景程序執行的，那個環境預設會找哪些 schema 不一定跟 SQL Editor 一樣。寫上等於直接給門牌號碼，不靠猜
  • 為什麼要先確認函式存在才排程：排程失敗是安靜的。名字打錯照樣建得起來、active 照樣 true，但每天半夜撞牆，可能兩週後才發現課表沒長
排程註冊在資料庫內部，跟你的瀏覽器無關 —— 關機、出國兩週，它照樣每天台灣 00:00 執行。
☢️ 絕對不要下 drop extension pg_cron; —— 會把所有排程連同設定一起永久刪除，救不回來。要停用請用 select cron.unschedule('daily-class-job');

00:00 那一刻真正發生的事
00:00 是「結算」，不是「關閉報名」。很多人第一次會誤會這點。
  • 00:00 之前 —— 教練持續等待，有人報就成立
  • 00:00 結算：有人（≥1）→ ✅ 成立，當天仍可加入（未滿 10 人，課程進行中也能插入）
  • 00:00 結算：無人（=0）→ ❌ 取消，之後有人報名也不開課、不扣課
為什麼刻意留這麼多人工面對面驗身分免費又可靠；金流一自動化就必須搬離 GitHub Pages。這套設計的成本是人力，換到的是緩期。
