# plan/ — 專案地圖與進度

這個資料夾裡的三個檔案是**互相連動的**。跟 `HANDOVER.md` 一樣是活文件，跟著程式碼一起版控。

```
plan/
├── roadmap-data.js            ← 唯一要改的檔案
├── fff-roadmap-steps.html     ← 讀 roadmap-data.js 畫出來
├── fff-architecture-map.html  ← 讀 roadmap-data.js 畫出「你在這裡」
└── README.md                  ← 這一份
```

---

## 怎麼更新進度

**只改 `roadmap-data.js` 一個檔案。**

打開它，找到剛完成的那一步，把 `done: false` 改成 `done: true`，存檔。

```js
{ n:18, t:'把 Project URL 和 Publishable key 放進前端', where:'前端', done: true,
```

存完直接重新整理瀏覽器，下面這些**全部會自己跟上**：

| 會自己變的東西 | 在哪裡 |
|---|---|
| `17 / 36` 那個數字和進度條 | 兩份都有 |
| 每一幕的 `3 / 6` 計數 | 步驟清單 |
| 路線圖上綠色實線的長度 | 步驟清單 |
| 紅色定位釘移到下一個沒做的步驟 | 兩份都有 |
| 「現在只做這一件事」那張卡 | 步驟清單 |
| 「剛走完／腳下／前方」三格 | 架構地圖 |
| 三個風險的「已解除」標記 | 步驟清單 |

**你不需要手動改任何一個數字。**

---

## 為什麼要這樣做

`HANDOVER.md` 曾經寫著「`db/` 已包含 00~06」，實際上只有 `00~05`。

那個坑的根因不是粗心，是**同一個事實被寫在好幾個地方**。改了一處、忘了另一處，文件就開始說謊 —— 而且說謊的文件比沒有文件更危險，因為你會相信它。

所以現在只有 `roadmap-data.js` 一個地方寫著真相，其他全部從它算出來。

---

## 開啟方式

雙擊 HTML 檔就能看，不需要伺服器。

⚠️ 但三個檔案**必須放在同一個資料夾**。HTML 是用相對路徑 `roadmap-data.js` 去找資料的，搬走其中一個就會變成空白頁。

---

## 改內容（不只是進度）時

- **改某一步的說明** → 改 `roadmap-data.js` 裡那一步的 `body`
- **加一個新步驟** → 在對應的 `acts[].steps` 陣列裡插一筆，編號 `n` 要連續
- **改版面或配色** → 改 HTML 檔的 `<style>`，資料檔不用動

`body`、`warn`、`ck` 這三個欄位都吃 HTML，可以用 `<b>`、`<code>`、`<ul><li>`。

## 跟 HANDOVER.md 的分工

| | 放什麼 |
|---|---|
| `HANDOVER.md` | **為什麼**：設計決定的理由、踩過的坑、絕對不能做的事 |
| `plan/roadmap-data.js` | **做到哪**：36 步走到第幾步、每一步的完成判準 |

兩邊都有進度摘要，`HANDOVER.md` 第十二節那份是給接手的人快速對焦用的。
**更新進度時記得兩邊一起改** —— 或者更省事的做法是：第十二節只寫「完整版見 `plan/`」，數字不要重複寫。
