☢️ 產出的 SQL 含完整姓名和手機

這一頁不連網（F12 → Network 自己驗，請求數 0），但它產生的檔案是個資。

① 先改 .gitignore 加一行 migration-local/，再產生檔案。順序反了的話，檔案可能在你改之前就被 Git 看到。
② 下載的四支 SQL 放進 migration-local/，絕不放 db/，絕不貼進聊天室。
③ 四支必須來自同一次產生 —— 客人的 id 是這一次隨機給的，混用不同批次會對不起來。

1把四個分頁貼進來

舊系統匯出檔 → 切到分頁 → 選取含標題列的整個範圍 → Ctrl+C → 貼進對應的框。

members 會員→ customers
PassLedger 堂數流水→ credit_ledger
LessonInstances 課次→ class_sessions
Bookings 預約→ bookings
日期上限 只匯入這一天（含）以前的課次。之後的課由我們自己的排程產生，重複匯入會變成同一時段兩堂課

2確認欄位對應

我猜的對應在下面。★ 是必填，紅色的代表我沒猜到，你自己從下拉選單挑。
挑錯的話後面全錯 —— 這一步花 30 秒，比事後查幾千列便宜。

兩個舊系統的特性已經內建：
① 會員是用「手機」認的，不是 memberId。手機會先正規化（去符號、+886→0）， 所以 0912-345-678 和 0912345678 算同一個人。
② 課次是用「classId ＋ 上課日期」兩欄一起認的。Bookings 沒有 lessonId， 它就是靠這兩欄指向一堂課。
