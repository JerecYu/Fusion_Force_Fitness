## 自動回應也加一段（免費，長期有效）

發送位置：OA Manager → 自動回應訊息 → 編輯現有那則

在「▌新系統快速說明」那一段後面接：

```
▌課程異動通知
訂課頁最下面有一格「請開啟［課程異動通知功能］」，
按一次、送出一則訊息，以後停課或改時間我們直接傳到這裡。
```

☢️ **回覆訊息（reply）不計費**，所以自動回應這條線是零成本的長期入口。
之後每一個來問問題的人都會看到，不用再群發。

## 怎麼知道有沒有人在按

```sql
select * from public.staff_push_coverage;
```

| 欄位 | 意思 |
|---|---|
| 客人數 | 系統裡的客人總數 |
| 已綁訂課 | 完成手機綁定、能訂課的人 |
| **已開通知** | **完成推播綁定的人 —— 看這一欄** |
| 訂課有但通知沒有 | 還沒按那顆鈕的人 |

發公告當天、隔天、一週後各看一次。

**長不動的話是文案或位置的問題，不是程式的問題** ——
那顆按鈕在訂課頁的最下面，要滑過整份課表才看得到。
如果一週後還在個位數，就要考慮把入口往上搬。

## 什麼時候可以停掉群發

「已開通知」涵蓋到**常來訂課的那群人**就可以了，不必等到全部。
判斷方式：最近兩週有預約的人裡，有幾成已開通知。

```sql
select count(distinct c.id)                                            as 最近有訂課的人,
       count(distinct c.id) filter (where c.push_user_id is not null)  as 其中已開通知
from public.bookings b
join public.customers c on c.id = b.customer_id
join public.class_sessions s on s.id = b.session_id
where s.session_date >= (now() at time zone 'Asia/Taipei')::date - 14
  and b.status <> 'cancelled';
```

這個比例過半，停課就可以只靠推播 ＋ 櫃檯打電話補那幾位，
不用再動群發。
